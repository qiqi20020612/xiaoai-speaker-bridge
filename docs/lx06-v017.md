# LX06 0.1.7：功能与代码精简（包含原生 LED 重构）

本版在用户已验收的 0.1.6 基线上精简实体、动态 Agent、空闲音量策略和展示专用采集，并移除独立灯环。版本号更新为 0.1.7，PR 待审阅，不自动合并或发版；开发与测试未连接或操作真实 LX06 / HA。自动化证据不能代替固件上的动画与音频验收。

## 最终 14 个实体

Unique ID 为 `<设备 UUID>_<后缀>`，不是可见的 Entity ID。保留原 ID、设备关联和用户的命名/启用选择；可写音量与 Conversation 控件继续按实际能力注册，完整 LX06 能力下恰好 14 个注册实体。

| 名称 | HA 类型 | Unique ID 后缀 |
| --- | --- | --- |
| 音箱（设备名称） | media_player | player |
| 播放文字 | text | announce_text |
| 执行文字指令 | text | send_text_text |
| 播报音量 | number | volume_tts |
| 蓝牙音量 | number | volume_bluetooth |
| 主音量 | number | volume_master |
| AirPlay 音量（%） | sensor | airplay_volume |
| 刷新状态 | button | refresh |
| 语音监听 | switch | listener |
| 重启桥接 | button | restart_listener |
| 重置会话 | button | reset_context |
| 可用内存 | sensor | memory_available |
| 桥接内存 | sensor | bridge_rss |
| CPU 负载 | sensor | cpu_load |

AirPlay 传感器附加 `raw_volume` 与 `raw_volume_unit: dB`；不可读时值为 unknown，不伪造数值。Media Player 保持标准 idle/playing/paused、原 source/active_source 等属性，不添加 activity。Coordinator 每次刷新只判断一次当前来源，播放器和自动音量复用；语音冻结快照仍按原来源优先级处理。

注册迁移同时匹配当前 config_entry_id、platform=xiaoai_speaker、domain 和完整 Unique ID。删去的 light、binary_sensor、sensor、select、switch、number 及旧发送 button 即使禁用/重命名也移除；其他条目、平台、域、相似后缀和用户配置不删除。保留的所有 Unique ID 不变，重启按钮继续使用 restart_listener 后缀以保护原 Entity ID；默认名称/功能变为重启桥接，用户自定义名称仍尊重原设置。引用已删除实体、Agent 参数或 idle 服务的自动化须由用户调整；其他服务 API 保留。HA 回退若要恢复被删实体的自定义 Entity ID/名称及旧选项，应恢复升级前 HA 备份，不依赖重新配对。

## 重启桥接与并发安全

按钮调用 POST /api/bridge/restart，202 仅表示接受调度。短寿命调用者复用现有 start.sh restart，强制 XIAOAI_SKIP_LISTENER_START=1；不主动操作 Listener、KWS、MPD、Shairport 或 Snapclient，不进入任务队列，不等待重启完成或承诺最终成功。入口检查语音/会话锁和活动任务；延迟调用和启动锁等待结束后，在发 TERM 前再次检查原语音所有权及 audio/session 门，发现新唤醒则放弃重启并保留当前实例的来源/音量状态，语音结束后可重试。成功停止后立即释放门锁，避免新唤醒等待启动探测；重复点击共享同一次调度，安装启动竞争会被共享安装锁阻止。已调度时拒绝新 API 工作，健康和状态仍可读。start.sh 的健康等待、日志、PID 身份与守护进程锁沿用，restart/install 锁不传给新守护进程。失败查看既有运行日志，原 HTTP/事件机制在恢复后重新连接。

原生设备页按钮没有本集成可设置的确认流程，未新增前端或动作。Dashboard 可用原生 button 卡片的 [tap_action.confirmation](https://www.home-assistant.io/dashboards/actions/#options-for-confirmation)：

```yaml
type: button
entity: button.your_existing_restart_button
tap_action:
  action: perform-action
  perform_action: button.press
  target:
    entity_id: button.your_existing_restart_button
  confirmation:
    text: 仅重启 XiaoAI Bridge，继续吗？
```

## 原生 LED 调用顺序

公开脱敏 Launcher 中，`show_led 1` 位于唤醒/录音之前，`show_led 2` 位于录音结束后的处理阶段，`show_led 3` 被注释，TTS 结束后执行 `show_led 11` 和 `shut_led 1/2/3`。远程任务只调用该顺序，不按数字猜测新动画：

| 阶段 | 原生调用 |
| --- | --- |
| 任务取得灯光所有权 | `show_led 1`，随后 `show_led 2` |
| Conversation、TTS 合成及播放 | 保持 2；删除合成/播放时重复申请灯锁的空操作 |
| 成功、无回复、不播报回复、失败、取消、超时 | `show_led 11`，随后 `shut_led 1`、`2`、`3` |

调用不触发录音或 STT，也不新增依赖、配置、颜色 API、常驻进程或 Cron 条目。缺少可执行的原生程序时跳过灯效；程序返回失败不改变任务结果，未完成的收尾保留标记以便以后重试。原生程序自身的耗时、退出语义与可见动画仍需真机检查。

语音收尾只有在既有周期 done 标记确认全部原生命令成功后，才允许省略任务的重复收尾。未确认成功时在灯锁下重试，失败继续保留恢复标记，不因语音已退出而丢失唯一的重试依据。

结束后的 AirPlay 重放会通过既有有界只读 DBus 查询确认当前 `Active=true`；断开、闲置或查询不可用时跳过，避免仅凭开机后留存的 `airplay_led.last` 显示旧音量灯。该查询位于原生收尾/释放灯锁之后，不控制播放或音量。

所有权沿用 `xiaoai_bridge.led.lock` 的 FD 6 与 `xiaoai_bridge.feedback` 的 PID/starttime。原生子进程不继承任务的锁。旧任务不能关闭或重新认领新任务的动画；语音预约/持锁时任务退让，保留被抢占任务的身份。语音按原链路完成收尾，释放后确认仍是同一任务：任务存活时续接原生处理动画，任务已退出时已确认语音收尾成功时只重放 AirPlay；未确认成功则保留/重试原生收尾。异常杀死的任务在启动、下一次任务或现有每分钟 Cron 上进行一次性恢复；永久阻塞的原生程序仍属于待真机验证的边界。

AirPlay 继续使用原音量灯及已审核 Guard（version=3）的 `draw` / `restore_led` / 有界 worker。它检查同一灯锁和所有权，任务期间保留最新发送端音量，结束后按 `airplay_led.last` 重放。原 AirPlay 脚本的 sysfs/RGB 音量绘制保留，Bridge 不再提供另一套 RGB 渲染器。设备具备原生命令及 AirPlay LED hook 时，安装前必须有匹配的私有 Guard；安装自动复用原激活工具启用它，已匹配的活跃 Guard 不动。缺少审核副本或源哈希改变会在业务文件替换前拒绝；活跃 worker 导致启用失败则恢复旧安装，等待 worker 结束后重试。绕过安装器或安装后自行撤销 Guard 的原脚本不遵守 Bridge 锁，属于不受支持的灯光协调状态。

## 删除与兼容性

- 删除 `custom_components/xiaoai_speaker/light.py`、LIGHT 平台、灯环翻译及打包条目。
- 删除 `/api/led` 分发、`device.sh led`、手动 LED capability/state、`led-color` JSON 操作、颜色/亮度计算、手动 RGB 状态读写和对应测试。
- `task-feedback.sh` 只保留原生命令、锁、所有权与 AirPlay 协调；清理旧配置示例和任务颜色说明。
- 旧 `verified.led` / `verified.task_led` 配置不重写、不阻止升级、不控制新版灯效；其他验证项和默认关闭的功能不变。
- protocol=1 保持。HA 0.1.7 可以连接旧 0.1.6，但不再提供手动灯环；音箱 0.1.7 缺少旧手动 LED 字段/接口，旧 Agent、空闲策略及展示字段按上述清单明确移除，健康、音量、文本及任务协议保留。升级前暂停新任务，先更新音箱，再更新 HA；过渡期旧灯环和 Agent 接口只会报错，不做中间功能验收。

仅清理本集成的精确旧注册项，完整清单见上文。KWS、OAuth、STT/TTS 实现、五分钟上下文、音量恢复、ducking 和 HA 队列算法未重构。Listener hooks 沿用之前的语音抢占与延期恢复；启动/现有 Cron 仅进行必要的孤儿灯效恢复。

保留复杂逻辑的原因：FD 6 与 PID/starttime 防止旧任务关闭新任务、PID 复用及语音优先；AirPlay 原脚本/后台 worker 不参与音频锁，需要已审核 Guard 才能在最新发送端事件下退让。收尾失败/孤儿任务标记用于有证据地重试，而非手动 RGB 状态。音量日志、独立通道版本、audio/session/config/OAuth/install 锁分别保护不同资源，不能合并成一个锁而引入等待环或丢失恢复。本轮去掉不做任何灯效切换的重复阶段调用，将一次性的 setup/available 状态直接并入 begin；没有新增灯效状态、调度或常驻服务。

6. 安装保留 UUID、Token、配置、启用状态与私有适配器；保存旧 Bridge/boot/Cron 快照，已有备份移到唯一的 `.backup.retained*` 路径，不删除。公开脚本清单/内部 SHA256 自动更新；HA 包不再包含 `light.py`、`binary_sensor.py`、`select.py`，音箱仍包含必要的灯光协调 helper。私有格式和适配哈希契约没有变化。

恢复旧 Bridge 二进制、配置/启用状态、私有 Listener/KWS、boot/Cron。快照记录 Guard 在升级前是否启用：原来启用且与恢复适配器精确匹配、哈希有效时保留；本轮新启用的恢复为原 LED 程序，原备份不删除。当前 Listener 的 OAuth 值不被旧快照覆盖；后续新增 Cron 项保留。失败目录、重试配置、较早备份仍保留。如果状态或哈希提示独立文件已更改，先保留全部副本并人工审阅，不强行删除恢复标记或覆盖原文件。
