# LX06 0.1.7：原生任务灯效与 0.1.6 升级

本版在用户已验收的 0.1.6 基线上移除独立灯环。版本号更新为 0.1.7，PR 待审阅，不自动合并或发版；开发与测试未连接或操作真实 LX06 / HA。自动化证据不能代替固件上的动画与音频验收。

## 改动与调用顺序

公开脱敏 Launcher 中，`show_led 1` 位于唤醒/录音之前，`show_led 2` 位于录音结束后的处理阶段，`show_led 3` 被注释，TTS 结束后执行 `show_led 11` 和 `shut_led 1/2/3`。远程任务只调用该顺序，不按数字猜测新动画：

| 阶段 | 原生调用 |
| --- | --- |
| 任务取得灯光所有权 | `show_led 1`，随后 `show_led 2` |
| Conversation、TTS 合成及播放 | 保持 2，不额外启动动画 |
| 成功、无回复、不播报回复、失败、取消、超时 | `show_led 11`，随后 `shut_led 1`、`2`、`3` |

调用不触发录音或 STT，也不新增依赖、配置、颜色 API、常驻进程或 Cron 条目。缺少可执行的原生程序时跳过灯效；程序返回失败不改变任务结果，未完成的收尾保留标记以便以后重试。原生程序自身的耗时、退出语义与可见动画仍需真机检查。

语音收尾只有在既有周期 done 标记确认全部原生命令成功后，才允许省略任务的重复收尾。未确认成功时在灯锁下重试，失败继续保留恢复标记，不因语音已退出而丢失唯一的重试依据。

结束后的 AirPlay 重放会通过既有有界只读 DBus 查询确认当前 `Active=true`；断开、闲置或查询不可用时跳过，避免仅凭开机后留存的 `airplay_led.last` 显示旧音量灯。该查询位于原生收尾/释放灯锁之后，不控制播放或音量。

所有权沿用 `xiaoai_bridge.led.lock` 的 FD 6 与 `xiaoai_bridge.feedback` 的 PID/starttime。原生子进程不继承任务的锁。旧任务不能关闭或重新认领新任务的动画；语音预约/持锁时任务退让，保留被抢占任务的身份。语音按原链路完成收尾，释放后确认仍是同一任务：任务存活时续接原生处理动画，任务已退出时只重放 AirPlay，不重复结束动画。异常杀死的任务在启动、下一次任务或现有每分钟 Cron 上进行一次性恢复；永久阻塞的原生程序仍属于待真机验证的边界。

AirPlay 继续使用原音量灯及已审核 Guard（version=3）的 `draw` / `restore_led` / 有界 worker。它检查同一灯锁和所有权，任务期间保留最新发送端音量，结束后按 `airplay_led.last` 重放。原 AirPlay 脚本的 sysfs/RGB 音量绘制保留，Bridge 不再提供另一套 RGB 渲染器。设备具备原生命令及 AirPlay LED hook 时，安装前必须有匹配的私有 Guard；安装自动复用原激活工具启用它，已匹配的活跃 Guard 不动。缺少审核副本或源哈希改变会在业务文件替换前拒绝；活跃 worker 导致启用失败则恢复旧安装，等待 worker 结束后重试。绕过安装器或安装后自行撤销 Guard 的原脚本不遵守 Bridge 锁，属于不受支持的灯光协调状态。

## 删除与兼容性

- 删除 `custom_components/xiaoai_speaker/light.py`、LIGHT 平台、灯环翻译及打包条目。
- 删除 `/api/led` 分发、`device.sh led`、手动 LED capability/state、`led-color` JSON 操作、颜色/亮度计算、手动 RGB 状态读写和对应测试。
- `task-feedback.sh` 只保留原生命令、锁、所有权与 AirPlay 协调；清理旧配置示例和任务颜色说明。
- 旧 `verified.led` / `verified.task_led` 配置不重写、不阻止升级、不控制新版灯效；其他验证项和默认关闭的功能不变。
- protocol=1 保持。HA 0.1.7 可以连接旧 0.1.6，但不再提供手动灯环；音箱 0.1.7 缺少旧手动 LED 字段/接口，其他实体、文本操作、服务及任务协议不变。先升级 HA 可减少旧灯环控件调用已删除接口的过渡期。

HA 在首次成功连接时，只移除当前配置条目中同时满足 domain=`light`、platform=`xiaoai_speaker`、unique_id=`<entry.unique_id>_led` 的旧注册条目。禁用、改过 Entity ID 的旧灯环也能处理；不删除其他实体、设备、用户配置或自动化，不卸载整套集成。引用旧灯环的自动化由用户自行调整。若要回退 HA 并恢复该灯环的自定义 Entity ID，需要升级前的 HA 备份；其他实体 Unique ID 不变。

KWS、OAuth、Agent、STT/TTS 实现、上下文、音量恢复、ducking、HA 队列和服务 API 未重构。Listener hooks 仅保留抢占标记并在语音结束后延期恢复灯光；启动/现有 Cron 仅增加孤儿灯效清理调用。

## 待授权的原地升级与恢复

1. 发布前只使用该 PR 对应且完整 CI 通过的 `generic-two-end-packages`，正式发布后使用同一版本 Release 附件。下载 LX06 ARM 包、HA ZIP、`RELEASE_NOTES.md`、`SHA256SUMS`，本地验证全部外部 SHA256；解包后再验证安装包内部清单。
2. 保存 HA 备份和设备私有恢复副本，保留现有 0.1.6 完整包及所有历史恢复目录。排空任务，暂停自动化新输入，确认语音/音频空闲；不要为部署清理认证或旧备份。
3. HA 更新替换集成并重启 HA 以加载新代码，保留原配置条目与设备。检查旧灯环消失、文本和音量实体的 Entity ID 仍在；后续重载不重建灯环，手动灯环自动化需要调整，不必卸载重配。
4. 把校验过的音箱包解压到 `/tmp` 的独立目录。现有有效的私有 format=4 / listener_hooks=4 / KWS guard=1 / AirPlay guard=3 会原样复用；不用上传私有脚本到 GitHub，不要重新复制旧认证配置覆盖现有值。安装器核对原始/输出哈希、锚点和已启用 Guard；缺少 AirPlay Guard 时先在工作站生成审阅副本，不加 verified 开关。已有匹配 Guard 原样保留，尚未启用的在安装事务中自动启用。
5. 在解包目录运行 `sh install.sh --dry-run`，确认版本、空间、适配契约通过，再运行 `sh install.sh --apply`。本次开发没有执行这些命令。不要从已安装或备份目录运行安装器；不需要卸载或中间升级。
6. 安装保留 UUID、Token、配置、启用状态与私有适配器；保存旧 Bridge/boot/Cron 快照，已有备份移到唯一的 `.backup.retained*` 路径，不删除。公开脚本清单/内部 SHA256 自动更新；HA 包不再包含 `light.py`，音箱仍包含必要的灯光协调 helper。私有格式和适配哈希契约没有变化。

任何非零退出都停止继续升级，先读 `/tmp/xiaoai_bridge.log`（及轮转文件）与 `/data/xiaoai_bridge.backup/status`。`failed_restored` 表示自动恢复完成；`recovery_required` 表示须用同一完整 0.1.7 解包目录的 `sh install.sh --rollback` 继续恢复，不用卸载代替回滚。成功后主动回退也使用该完整包的 `--rollback`。

恢复旧 Bridge 二进制、配置/启用状态、私有 Listener/KWS、boot/Cron。快照记录 Guard 在升级前是否启用：原来启用且与恢复适配器精确匹配、哈希有效时保留；本轮新启用的恢复为原 LED 程序，原备份不删除。当前 Listener 的 OAuth 值不被旧快照覆盖；后续新增 Cron 项保留。失败目录、重试配置、较早备份仍保留。如果状态或哈希提示独立文件已更改，先保留全部副本并人工审阅，不强行删除恢复标记或覆盖原文件。

已启用 Guard 的原始备份必须可读且符合 review 的 source SHA256；缺失、被 Guard 输出替代或独立修改时，安装预检拒绝，回滚/卸载及独立 Guard 工具也停止。不会在原 AirPlay hook 仍依赖 helper 时移走 Bridge 目录；先恢复经审核的原始备份，不能用 Guard 本身充当原文件。

## 自动化与最小真机验收

`tests/test_native_led.py` 在隔离目录执行实际 shell/Bridge、脱敏 AirPlay Guard 和 HA Entity Registry：正常播报、对话有/无回复、原生程序缺失/失败、取消/超时、SIGKILL、灯锁竞争、语音预约/抢占、旧任务所有权、AirPlay 延期重放、旧字段/状态忽略、旧 API 404、精确实体清理。安装故障测试覆盖 0.1.6 升级成功、Bridge/Listener 启动失败、手动回滚、私有状态与更晚 OAuth 值保留。现有音量、五分钟上下文、KWS、HA 服务/队列和启动测试继续运行。

CI 的 jq 1.6、BusyBox、ASan/UBSan、ARM QEMU、HACS/hassfest、安装包校验提供软件证据；不会证明固件原生程序退出行为、动画时长、麦克风首字、发送端滑块或真实资源峰值。

待用户授权安装后，按以下最小顺序验证并记录结果：
