## HA 音量显示

### 问题与行为

v0.1.9 的 Number 和 media_player 等待音量请求完成后立即刷新设备状态。`/api/state` 的音量来自缓存 Probe，该刷新可能仍返回设置前的值；请求等待期间也没有显示目标，容易使用户重复提交。语音或 Duck 期间，已确认的设置可能只更新期望值，硬件稍后才应用。

三个原生 Number（主音量、播报音量、蓝牙音量）和 media_player 共用按通道的临时显示值。请求发出前立即通知原有 Coordinator 的实体监听者；同通道的较新输入立即显示，设备写入按提交顺序执行。只有收到成功确认并完成原有 Store 持久化的通道，才更新期望值。失败移除该次未成功的显示目标，恢复最近成功值或稳定观测值，并保留原生错误反馈；较早响应和错误不能覆盖较新输入，`all` 的部分成功仍逐通道保留。

media_player 继续按原有音源映射通道，Number 的实体身份、范围、能力门控和默认启用状态不变。相对音量操作以当前显示目标为起点，连续操作不会反复从旧缓存计算。

后续 [Codex Review](https://github.com/qiqi20020612/xiaoai-speaker-bridge/pull/10#discussion_r4306465496) 发现文字音量成功回调只更新 Store，未更新旧的显示保护。例如 HA 设置 75% 后，文字指令成功设置 40%，实体仍可能显示 75%，相对加音量会误算为 85%。本次让原 `volume_plan` 成功回调在持久化成功后，同步更新对应通道的确认显示、Probe 边界和查询代次，并通知原有实体监听者；规划、非法提交和 Store 失败不更新显示。保留尚未完成的 HA 输入，若其失败则显示最近成功的文字目标；旧查询不能覆盖新的成功提交。仅改 HA 内部调用，不改变协议、音箱执行、音量版本、锁或 Journal，也不为回调重复发送设备控制。

另一项 [Review](https://github.com/qiqi20020612/xiaoai-speaker-bridge/pull/10#discussion_r4306506767) 指出取消窗口：设置 70% 仍在等待设备响应，后来排队的 80% 被取消时，原记录只保留最新请求，显示会回到旧值 60%，而非仍在执行的 70%；此时相对加音量会计算错误。现按通道保留尚未结束请求的顺序，显示最新有效目标；成功、失败或取消仅按请求身份移除自身，最新请求取消后恢复前一个仍有效的目标，再回退到最近成功值。只保留活跃 HA 调用的内存引用，结束后清理；不增加任务、持久状态或设备控制重试，实际写入顺序和互斥不变。

### 哪些状态可更新实际值

复用原有轮询和事件刷新，不新增轮询、计时任务或控制重试。原三个设置入口中的立即刷新已移除；一次明确设置仍只向每个解析后的通道发送一次控制请求。Bridge 重启后既有的期望值恢复继续保留，并与用户设置使用同一 HA 写入互斥，取锁后才读取最新期望值。

Probe 的 `updated` 是完成时间，而非 mixer 采样时间；C Bridge 同一时刻只运行一个 Probe。设置前采样的 Probe 可能在成功确认后才结束，不能将第一次 HTTP 返回或单纯较新的时间戳直接视为实际音量已经更新。因此：

- 查询开始时记录 HA 音量请求代次，跨越新设置、成功或回滚的旧查询不能更新音量显示或持久期望。
- 成功后第一次查询用现有 `instance_id` 和 `updated` 建立缓存边界，不立即导入该缓存。等待更新的 Probe；若第一代更新值仍与目标冲突，跳过这一代，排除已在途的旧采样。之后的有效实际值可以与目标不同，不会无限等待相等值。
- 通道为 `null`、非有效百分比、状态 stale、有 voice/audio 活动、Journal 待恢复或 HA 任务仍在执行时，不确认实际值。设备忙时的临时衰减值不会写入 Store，空值保留最近有效显示。
- 缺少 Probe 身份或有效时间时保留目标，等待后续可确认状态；离线和 stale 仍按原实体规则显示不可用。Bridge instance 改变后重新建立边界。

显示保护只保存在 HA 内存中，按固定音量通道保存有限条目，不写新存储格式，不依赖 TTL，也不据此重新发出控制。为辨别旧采样，实际值确认可能比首次状态刷新晚；期间目标保持可见，不能把目标显示当成硬件已经生效的证明。

### 兼容性与恢复

本项运行代码仅改 HA 集成，音箱端音量版本、HA 新目标优先、voice/duck/tts Journal、发送端调音保护、锁与恢复路径不变。音源策略、协议、配置、实体 Unique ID、LED、原生录音和任务控制均沿用 v0.1.9。Store 写失败不留下内存中的新期望值，也不为回滚界面发送额外硬件写入；实际可能已执行的写入由后续有效状态确认。卸载/重载后丢弃临时显示，继续使用原有持久期望和设备同步。

## AirPlay Duck 的 LX06 整数刻度恢复

### 真机发现与根因

用户在 v0.1.9 真机复现：AirPlay 播放时 TTS 将 master 从 69% 降至 10%，iPhone 中途调音后，`sender_recovery=true` 的 Duck Journal 保持 PENDING，mysoftvol 留在 10%。提供的观测为 Shairport 4.3.5、standard、主/Remote D-Bus Volume 均为 -18，ALSA DB_SCALE 为 min=-51.00 dB、step=0.20 dB、整数范围 0–255。原目标模型给出 -15.70 dB，但该机 `amixer -- sset mysoftvol '-45.80dB'` 返回 Invalid command/1；`amixer cset name=mysoftvol 26,26` 成功。

v0.1.9 将正确的目标 dB 交给未经真机写入验证的 amixer 命令量化。旧测试替身会去掉 `--` 并主动接受 dB 写入，未暴露固件命令不兼容。本次不判断其他未经验证的 dB 参数变体是否可用，直接采用已确认的整数 `cset` 形式。

### 最小修复与保护

保留原 Shairport 曲线和配置/PID/starttime 校验，仅替换活跃、非静音发送端的硬件写入。C helper 按实际 `cget` 的整数范围和 DB_SCALE 计算两声道刻度；TLV 按精确的 centi-dB 解析，不将浮点小数近似为另一条曲线。转换遵循 [Shairport 4.3.5 首选的 dir=0](https://github.com/mikebrady/shairport-sync/blob/4.3.5/audio_alsa.c#L371-L379) 与 [ALSA DB_SCALE 最近刻度、中点向上规则](https://github.com/alsa-project/alsa-lib/blob/master/src/control/tlv.c#L329-L351)：

- `raw = min + nearest((target_centi_db - tlv_min_centi_db) / step_centi_db)`，中点向上，全程使用整数求商和余数，支持非零 raw min 和奇数 centi-dB 步长。
- 本例 -15.70 dB 对应 176.5，写 `amixer cset name=mysoftvol 177,177`，实际 -15.60 dB；-45.80 dB 则精确对应 `26,26`。这是明确的量化结果，不是忽略小数误差或假定百分比曲线。
- 写前继续原子提交原有 `sender_recovery` 标志，写后用 `cget name=mysoftvol` 读取两声道，再用同一 helper 的 `--verify` 重新校验配置/TLV 与目标；左右都必须等于计算刻度，且目标与写前一致，才继续原有 D-Bus 主属性/Remote 提交及进程校验。
- 控件必须是准确的 mysoftvol/index 0、可读写双声道 INTEGER，范围合法、raw step 为 0/1，且单一无硬件 mute 的 DB_SCALE 有效。重复/缺失字段、未知类型、越界、非法/过精度 TLV、只写对一个声道、返回成功却未生效、读回失败或目标变化均保留 Journal，等待原有恢复机制重试，不回发发送端音量。

静音仍须先确认 Remote 的 -144，再沿用原百分比基线解除 cap；已确认停止时的原值恢复也保留，不改成未经证明的发送端模型。两个原百分比分支移除多余 `--`，使用其余正常恢复路径已有的 `amixer sset` 形式。Volume Lock、Journal、HA 新版本优先、独立 TTS/Bluetooth 恢复、duck→voice 交接和 SIGKILL 恢复不变；不修改 xiaoai-patch、私有 KWS/TTS、Listener、LED 或 Shairport 配置，不新增常驻组件。

### 验证边界

严格的传输替身只接受已确认的 `cset name=mysoftvol 左,右` 整数契约，并明确拒绝旧 `-- sset … dB` 和其他未证明的 dB 变体；记录真实参数顺序，维护可读回的两个整数声道，不再按 dB 字符串硬编码成功。新增真机故障场景测试在修复前失败，修复后通过；同时测试返回 0 但未生效、单声道错误、读回失败/错误 TLV 后保留 Journal、独立通道可恢复及随后重试成功。native 与 ASan/UBSan 模块回归本地 212 项通过；ARM/QEMU 另外检查整数目标、半步舍入和双声道验证。

周边 Duck、TTS 衰减时机及实际 Probe 的 68 项本地回归通过；C 编译、ASan/UBSan、ShellCheck、Ruff、元数据、隐私和本次文档 33 个本地链接检查通过。固定 jq 1.6、真实 BusyBox 与完整包构建沿用原 Linux CI。

这些是依据用户真机观测建立的离线契约与模拟结果。本轮没有连接、改写或部署真实设备；新 `177,177` 恢复、连续 iPhone 调音、静音/停止、并发和听感仍须后续真机验收，不能把模拟或 QEMU 写成 ALSA 硬件通过。
