# LX06 v0.1.8：语音关键路径与离线测量

当前是开发构建，未创建 v0.1.8 Tag/Release，未连接、部署或操作真实 LX06 / Home Assistant。发布基线为 v0.1.7（fa019c92）；main 上的交接提交只增加文档。**本轮不能证明 LX06 实际提速、首字完整性或 CPU/RSS 验收通过。**

## 实际改动

- 本轮 Listener 的 starttime 已由 bridge_voice_detected 取得，显式传给 owner 和 voice Journal；它在同一存活进程内不可变。其他 owner/Journal 调用默认仍重新读取，不缓存外部进程身份。
- Journal 和恢复各自的一份 Shairport 回复，用一次 AWK 取得 Volume/Active，保留独立首个匹配、缺失字段及单属性调用契约。
- 已有 JSON 字符串直接交给 atomic_json 写入临时文件，省去管道和 cat；旧 stdin 入口仍可用。验证、0600、rename、通道版本和锁边界保留。
- 失败查询的 stdout 整体丢弃，再赋未知值。原先非零退出仍可能采信部分 DBus 输出，或把 MPD 的 play 与 unknown 拼接后当成确认不活跃。新增失败注入先复现，再修正；这是失败分支的正确性修复，正常观测不变。

录音前、需要衰减且无旧恢复/duck 的受控路径，外部调用计数如下。数字不包含观测器自身，不代表所有错误或竞争分支：

| 调用 | v0.1.7 | v0.1.8 | 原因 |
|---|---:|---:|---|
| sed | 3 | 1 | 减少两次重复自身 starttime 读取 |
| awk | 10 | 7 | 上述两次身份解析及一次重复属性解析 |
| cat | 2 | 0 | Journal 创建和 applied 更新直接写已有字符串 |
| Shairport DBus | 2 | 2 | 保留不同采样时刻 |
| BlueZ / MPD | 各 1 | 各 1 | 保留多源/未知观测 |
| amixer get / sset | 3 / 2 | 3 / 2 | 保留基线、阈值判断及同步衰减 |
| JSON validate / chmod / rename | 各 2 | 各 2 | 保留提交验证及事务 |

该路径减少 7 次外部命令执行，并减少相应管道子 Shell；不将调用次数换算为固件毫秒数。

## 保留的语义与未实施内容

两次 AirPlay 查询仍分别位于 Volume 锁内的恢复基线和锁释放后的音源快照。两者之间可能启停或发送端调音；回归强制第一份 inactive、第二份 active，检查两份信息各自保留。

不按最高优先级提前停止探测，未查询不伪装 false。继续保存 active_sources、observed_sources 和 uncertain，HA 使用原优先级。现有未知状态下的自动音量规则没有在本轮重新定义。

不实施缓存快路径。C Probe 缓存、HA 策略文件与语音实时快照不能互换，Probe 本身没有完整 MPD 观测；缺少硬件收益证据支持增加缓存失效协议。

不重写 locks.sh，不改变 LED/Volume/Audio/Session 锁、原预算或继承 FD。保留 voice_begin 在完整快照之后、Audio 等待之前的位置，以及 announce 抢占、duck 原值交接、Session 先释放再等 Audio 的顺序。

录音命令、通道、提示音及 0.15 秒等待、STT 流式上传、Microsoft STT、原 Agent/上下文/OAuth 和豆包/回退链保留。14 个 HA 实体、Unique ID、protocol=1、配置、服务及安装事务不变；不恢复 Agent Select、idle 策略或 RGB 系统。

## 可选诊断

复用现有有界 profile，不增加常驻进程、定时任务或音频文件：

| 环境 | 含义 |
|---|---|
| 默认 | 原录音命令直接运行，无 trace helper、PCM 解析或新增音频缓冲 |
| XIAOAI_PROFILE=1 | 原阶段与 recording_first_output；只证明首字节，可能是 WAV 头 |
| 再加 XIAOAI_PROFILE_DETAIL=1 | 细分 LED/Volume 等待、mixer、Journal、policy/AP/MPD/BlueZ 查询 |
| 再加 XIAOAI_PROFILE_PCM=1 | 在已有透传 helper 中识别完整 PCM 帧，输出 recording_first_pcm |

First PCM 仅支持 RIFF/WAVE 整数 PCM，按实际 chunk 跳过额外内容和奇数字节 padding，支持跨 read 的 header/frame，不假定 44 字节。不保存 PCM，不等待凑帧再转发；先透传当前块，再进行可选检查和日志，成功后停止检查。未知格式或截断不制造 PCM 时间。原 4096 字节透传块保持，新增固定状态只存格式头/计数。

观察点代表完整帧已通过软件 tap，包含原录音 silence/filter 和可能的下游背压，不能代表 ALSA open、ADC 首样本或人声首字。PCM 开关单独设置不会在普通录音路径启动 helper。诊断失败不丢字节；开启诊断有观测开销，不能承诺与无观测完全相同时序。

profile 只含 PID、固定 phase、uptime 和 cycle，约 64 KiB 轮转，不含文本、音频、配置、凭据或响应。沿用 /proc/uptime 同一 boot-time 单调基准；实际固件分辨率待核实，输出小数位数不代表精度。

```sh
python3 tools/profile_report.py /path/to/reviewed.profile
python3 tools/profile_report.py /path/to/reviewed.profile --summary
```

默认 CSV 不变。summary 输出相邻阶段及明确 cycle 内 wake/launch/PCM 区间的样本数、中位数、nearest-rank P95、最大值。缺失观测不补零，旧 PID 记录不推断跨唤醒总时间。

## 可复现的离线对照

55cc168 是仅增加诊断的 v0.1.7 运行逻辑，用作相同埋点的基线；不是正式 v0.1.7 发布包，没有运行优化或版本升级。原 Tag 也可输入工具，但没有 First PCM，不能将缺失值与新值比较。

```sh
python3 -m tools.benchmark_wake --baseline 55cc168 \
  --samples 30 --query-delay 0.03 > offline-wake.json
```

工具只复制指定 ref 的公开 tracked speaker 文件，在临时目录编译实际 JSON helper；硬件、策略、录音均为合成替身。两端使用相同工作站单调时钟文件（5ms 更新）、真实内核 FD 锁与相同 wrapper。默认每场景/版本暖机 1 次，再交替 A/B。输出各阶段分布、调用计数和快照；路由或音频字节不同立即失败。

query-delay 是人为注入的每次查询延迟，**不是 LX06 DBus/MPD 开销**。工具不模拟 KWS/Guard、原日志/ubus、真实 LED/mixer、miplay、STT 或 provider；提示音只保留原 0.15 秒等待。Python flock 替身、clock updater、工作站进程启动和调度影响结果。此工具验证机制和输出等价，不提供设备 CPU/RSS 或音频验收。

本轮工作站对照：基线 55cc168、候选 2a4113a；macOS arm64、Python 3.14.6、Apple Clang 17。每场景/版本暖机 1 次、采样 30 次、交替顺序、每次查询注入 30ms，PROFILE/PCM 开启、DETAIL 关闭。测试期间没有并行运行测试套件。完整相邻阶段及 cycle 总区间见 [CSV](benchmarks/v018-offline.csv)。所有场景的快照、音频字节和调用计数检查通过。

下表每格为中位数 / P95 / 最大值，单位 ms；均是上述合成条件，不能外推到 LX06。

| 场景 | wake→launch 基线 | wake→launch 候选 | launch→PCM 基线 | launch→PCM 候选 |
|---|---:|---:|---:|---:|
| idle | 557.5 / 575.0 / 589.0 | 538.0 / 550.0 / 550.0 | 51.0 / 59.0 / 59.0 | 47.0 / 55.0 / 61.0 |
| airplay | 564.5 / 577.0 / 580.0 | 540.5 / 559.0 / 564.0 | 47.0 / 54.0 / 58.0 | 47.5 / 53.0 / 59.0 |
| bluetooth | 563.0 / 580.0 / 583.0 | 542.0 / 558.0 / 559.0 | 47.0 / 54.0 / 55.0 | 46.5 / 54.0 / 55.0 |
| mpd | 562.5 / 576.0 / 587.0 | 539.5 / 557.0 / 562.0 | 49.5 / 55.0 / 55.0 | 48.0 / 54.0 / 56.0 |
| multiple | 561.0 / 580.0 / 584.0 | 540.0 / 559.0 / 592.0 | 51.0 / 57.0 / 58.0 | 50.5 / 55.0 / 55.0 |
| unknown | 558.0 / 587.0 / 588.0 | 539.5 / 556.0 / 561.0 | 47.0 / 54.0 / 54.0 | 48.0 / 54.0 / 60.0 |

本机合成 wake→launch 中位数减少 18.5–24.0ms，但 multiple 场景最大值从 584.0ms 增至 592.0ms；launch→PCM 变化小且方向不一致，保留全部异常值。这个实验只支持调用减少与机制等价，没有证明硬件提速，也不能据此认定主要瓶颈。CPU/RSS 未在此合成环境作设备验收。

同一 Zig 0.14.1、-Os/-s、静态 ARM hard-float 构建，v0.1.7 二进制为 142764 字节，候选为 143732 字节（增加 968 字节，包含可选诊断代码）。这是文件大小对照，不代表 RSS；没有新增常驻进程或运行数据缓存。

## 后续 LX06 验收

启用 profile 须另获设备授权，使实际 Listener 的启动环境继承变量；工作站 export 或只重启 Bridge 不保证生效。本轮不改私有 KWS/Listener/Agent/TTS/认证文件，不执行设备安装器（包括 dry-run）。

同一设备、配置和录音命令，使用相同诊断条件，分别记录：

1. 已有 WAKE_RX→CLEANUP_DONE→Guard 返回→wake。wake 晚于客户端接收，树莓派命中与 LX06 时钟不能直接相减。
2. wake_setup_begin、wake_led、wake_volumes、wake_snapshot、wake_event、wake_audio_ready、条件性的 wake_attenuated、recording_launch 及 First output/PCM。
3. 原 SOUND_BEGIN/SOUND_END 和 0.15 秒等待。区分客户端清理、Bridge 准备、锁竞争、提示音、录音命令启动与 PCM；不扩大本版去改 KWS/预录缓冲。
4. 每场景至少 30 次，保留失败/异常值、样本数、中位数、P95、最大值，以及暖机、Probe 重叠、锁持有者和真实播放状态。
5. 空闲、三源分别播放、快速切源、多源、HA/发送端调音、TTS 抢占、STT 空结果/失败、断网、Bridge/Listener 重启和恢复；连续“小爱同学打开灯”的首字须声学验证。

复用 tools/resource_probe.sh 分别观察 Bridge/Listener 进程树、CPU ticks、RSS/高水位、可用内存、进程/临时文件数；记录 CLK_TCK 与采样开销，不用 load average 代替 CPU%。正常关闭诊断与开启诊断另作对照。CPU、RSS、磁盘、固件时间精度与真实首字本轮均未验证。
