# LX06：jq 1.6、录音关键路径与结束灯修复（0.1.6）

本版依据 2026-10-13 真机问题交接，目标是从已验证的稳定 **0.1.3 直接升级到 0.1.6**。本轮只修改公开代码、运行隔离测试和发布，没有连接、部署或操作 LX06 / HA。0.1.5 已发布，因此使用新版本号，不覆盖旧 Release。交接中的用户临时修补只证明错误码改变，不能视为完整语音链或 HA 已验收。

## 修复及证据边界

| 问题 | 处理 | 证据 / 尚需验证 |
|---|---|---|
| P0：正常文字被判 invalid_request | `text.sh` 用 `explode \| index(0) \| not` 检查 NUL；正常中英文、引号、换行、emoji 可用；真 NUL 与错误类型在业务动作之前拒绝 | 真机交接已证实旧错误；本地及 CI 使用真正 jq 1.6 复现旧谓词并回归新谓词。完整语音与 HA 动作须复验 |
| P1：唤醒后反复启动 jq | 现有 Bridge 新增固定 `--json-op` 操作：快照、音量记录、接管、恢复与最终回复构造。录音前正常路径（包括已有 duck 记录）为零次 jq；来源查询仍同步完成于衰减前，原录音命令保留 | 测试在 jq 被禁止时走到实际 mock 录音并恢复新目标；固定操作与 jq 1.6 对照来源/优先级 216 种、接管 48 种组合。真机每次 jq 约 480 ms 是交接测量，不是新版本实测提速 |
| P1/P2：播放结束后灯滞留 | 最后一次 TTS 及临时音量恢复完成后，当前语音可先发送合法 LED 11 与 shut 1/2/3，再做回复序列化 / HA guard 清理；父 Listener 的同一周期结束操作幂等 | Linux 隔离测试阻塞 guard 清理，确认熄灯命令先发且 voice、音量记录、音频/LED 锁仍在；正常/取消各一次结束动画。真实 1–2 秒延迟尚无完整阶段证据，不认定为 show_led 本身慢或父恢复慢 |
| 输入与异常边界 | Agent ID 全串匹配，拒绝嵌入/末尾换行和畸形 snapshot；有限大小的严格 JSON 解析；帮助程序失败不能提交其已输出的半成品；恢复 cap 用精确数值比较 | 真 jq 1.6、ASan/UBSan、畸形 UTF-8/NUL/重复键/深度/长度、失败注入。非法负 cap 拒绝；不推算发送端目标 |
| 诊断 | 文本错误留下有界 `pid/error`；可选阶段 trace 用同一 `/proc/uptime` 时钟和语音周期串起父子进程 | 不记文字、凭据、响应或音频；默认无性能 trace。首次录音输出可能是 WAV 头，不能当作首个麦克风采样时刻 |

jq 1.6 的字符串实现会把 NUL 搜索退化为空串搜索，见 [上游 issue 1732](https://github.com/jqlang/jq/issues/1732)。CI 从 [官方 jq 1.6 发布页](https://github.com/jqlang/jq/releases/tag/jq-1.6) 下载 Linux 二进制并校验官方 SHA256，所有音箱脚本测试都使用它；测试中的硬件和网络仍由隔离 fixture 替代。JSON 固定操作不加载配置，不接触锁/硬件/网络，也不直接写恢复文件；Shell 继续在原音量锁内原子提交同一记录格式。没有增加常驻服务。

## 保留的安全与兼容行为

- 原音量锁、逐通道恢复记录、失败有界重试、最新 HA 目标优先和 AirPlay 发送端不确定性保护均保留。LED 提前结束不会释放父进程的音频 / LED / voice 所有权；恢复失败仍保留记录。
- KWS 监督、原录音参数、STT、错误提示、OAuth 双锁与当前凭据保护、五分钟滑动上下文和既有 protocol=1 / HA 实体 ID、服务、便捷操作不改变。
- 音乐避让及 `verified.announcement_ducking` 仍默认关闭；v0.1.7 原生任务灯效默认工作，不再受灯效验证字段控制。没有自动开启 verified，没有改 Shairport 曲线或绕过任务取消。
- 上版安装事务、原二进制/私有适配/enable 快照、失败自动恢复及旧 format=1 回滚路径保留，不增加未部署中间版本的专用历史恢复逻辑。安装语音空闲检查继续同时读取 PID / starttime；不能把两个字段当单个 PID。

## 私有适配迁移（必须）

新版 `review.json` 为 **format=4、listener_hooks=4、kws_guard=1、airplay_led_guard=3**。新增录音观测入口与幂等结束 LED 属于 Listener 契约变化；旧 format=1/3 在文件替换之前拒绝，不能只改 review 数字。失败回滚不要求升级前 0.1.3 的适配满足新格式。

使用本版源码里的工具、Python 3.14，从保存的**原始** Launcher、KWS guard、AirPlay LED 脚本重新生成；不是从已经适配的 listener.sh 生成，也不要复制认证配置给他人：

```sh
python3 speaker/tools/prepare_adapters.py \
  --listener .private/original-launcher \
  --kws-guard .private/original-kws-guard \
  --airplay-led .private/original-airplay-led \
  --output .private/prepared
```

审阅三个 diff 与原始/输出 SHA256，特别核对：初始化只一次；KWS 检测 hook、LED 1、同步音量记录/衰减、原录音、LED 2、STT、文本入口、幂等 LED 11/shut、最终音量恢复的顺序。原 `/data/listener` 在运行时加载，OAuth 配置不复制到公共适配模板。将生成文件放入本机私有部署包的 `xiaoai_bridge/adapter/`；不上传私有部署包或认证配置到仓库。未知结构由生成器拒绝后人工审阅。

## 用户后续升级与失败恢复

这些是供用户另行执行的设备写入步骤，本轮没有执行。若现场仍是临时修补后的 0.1.5，应先确认实际版本和原 0.1.3 快照；不能仅凭旧记录假设已经回退。本版重点验证的恢复起点是稳定 0.1.3。

1. 下载 v0.1.6 的四个附件，在同一工作站目录执行 `sha256sum --check SHA256SUMS`（macOS 用 `shasum -a 256 --check SHA256SUMS`）。保存当前 HA 组件/配置，以及本机私有的升级前 Bridge、Listener/KWS/OAuth、boot/Cron 副本和哈希，权限 0700/0600，避免公开。
2. 按上节生成并审阅 format=4 私有适配。保留 UUID/token、原 enable 和 verified 状态；新增功能先保持关闭。稳定 0.1.3 无需先安装 0.1.4 或 0.1.5。
3. 排空 HA 队列，暂停会产生任务的自动化，避免语音/音量新输入；安全认证读取确认 voice.active=false、audio_active=false、state_stale=false。0.1.3 没有新版 POST 安装门控，因此检查到停止之间仍要保持空闲。核验原语音和 KWS 单实例、原件哈希及无未完成事务。
4. 检查 /data、/tmp 和内存。安装器要求新包 KiB + 2×原 Bridge KiB + 512 KiB，再留日志/音频并发余量；不要删除旧备份腾空间。部署包放在 /tmp，不能从正在运行的 /data 安装目录升级。若现场已经启用旧 AirPlay LED guard，先按 [安装说明](install.md) 用旧工具审核移除；稳定 0.1.3 没有启用过则无需此步。
5. 在完整解压包中核验内层 SHA256，执行 `sh install.sh --dry-run`。任何拒绝先解决；不可跳过适配校验。预览通过后自行执行 `sh install.sh --apply` 并等待退出。应为 installed、version=0.1.6、原 enable 保留、Listener hooks=4 / KWS 初始化就绪；再核验部署清单和原件。
6. 安装同版 HA 包或 HACS 更新，沿用现有集成/实体/配对。可先升级 HA 验证旧协议，但新功能验收需两端到新版；不删除 registry。
7. 非零退出即停止。`failed_restored` 后核对原二进制、私有适配哈希、enable、include 数量、当前 OAuth、Listener/KWS 和原语音，不能只看状态名。`recovery_required` / prepared / replacing 时，用**同一完整 0.1.6 包**执行 `sh install.sh --rollback`；保留 .failed/.retained/.incomplete 及快照。不用 --uninstall 代替恢复，不用旧 Listener 全文件覆盖已刷新的凭据。

有限恢复测试不等于掉电、永久 I/O 故障或硬件损坏已验证。发送端与本次 cap 无法区分时仍保留 pending；可在后续测试中用发送端新目标或现有 HA master 接口明确目标，不能删记录或猜 dB 映射。

## 真机阶段测量与验收清单

默认 trace 关闭。用户独立授权测试时，在现有 Listener 启动环境设置 `XIAOAI_PROFILE=1`，让它按原启动链加载 format=4；测试后撤销环境变量。`/tmp/xiaoai_bridge.profile` 与 `.1` 各约 64 KiB，含 pid/phase/uptime/cycle，无音频/文字。以同样环境分别测基线与新版；有 trace 的额外启动/文件计数开销应记录。将已审阅的阶段日志复制到本地，用：

```sh
python3 tools/profile_report.py .private/copied.profile > .private/phases.csv
```

CSV 保留原四列并增加 cycle/from_pid，连接同一次语音的父子进程；旧无 cycle 记录继续按 PID 解读。重点比较 `wake → recording_launch → recording_first_output`、`tts_finished → voice_led_off_sent`、`result_serialize_begin/done`、`guard_end_begin/done`、`listener_text_return` 与 `voice_restore_begin/done`。首次 recorder 输出可能是 WAV 头；需独立麦克风/音频测量才能证明首采样与实际录音完整度。不能用工作站或 QEMU 时间推算 LX06 总延迟。

| 顺序 | 用户亲测 | 通过条件 |
|---|---|---|
| 1 | 默认配置，正常中英文语音；唤醒词后马上连续说命令 | 录音实际更早开始、首字完整；LED 1/2/11 各合法、仅一次结束；上下文和恢复正常。若仍吞首字，保存阶段证据 |
| 2 | LED 分段计时，短/长 TTS、无回复、空 STT、错误提示 | 分清播放完成、临时恢复、序列化、guard 与父恢复；无残留动画、无过早放行其他音频 |
| 3 | 豆包 / Microsoft / Google 正常及回退，极短播放、超时 | 本次播放器的 playing 状态可信，失败不虚报，notifyvol/master/bluetooth 各自恢复 |
| 4 | HA 原实体、便捷文本、指定 Agent、静默文本、播报、五分钟滑动 / 过期上下文 | 与稳定 0.1.3 已验收行为一致；此前 HA 在真机测试时被禁用，必须重验 |
| 5 | AirPlay 音量同步；语音 / TTS 期间手机拖动音量及 HA 新目标 | 不双重衰减，不覆盖新目标；不确定时 pending 明确且可安全解除 |
| 6 | 取消、抢占、优先级、幂等、锁竞争、一次 401 / OAuth 刷新 / Listener reload | 正确恢复且任务不重复，单一 KWS 实例，当前凭据保留 |
| 7 | 基础功能通过后验证原生任务 LED，再单独验证音乐避让 | 原生 1/2/11/shut、AirPlay 灯退让和发送端竞争均正常 |
| 8 | 另行授权的失败安装/rollback、重启、daemon 退出、≥31 分钟空闲与连续任务 | 能恢复确切升级前 0.1.3，原音频服务不受损；整机、Listener、短寿命 worker 的 CPU/RSS/HWM/空间稳定 |

本版**没有实现预录缓冲**，不承诺仅减少 jq 就能完全消除首字丢失。真实 Launcher 的 KWS 决策、提示音与固定间隔仍在；8 通道录音到 2 通道 KWS 的时间/通道关系、缓冲寿命和资源峰值尚未确认。预录需要另行设计并默认关闭，在完整保存音量/取消/设备安全前提下验证。非协作的原 ledserver / KWS 离线灯 / 物理按键、永久锁争用、真实驱动与网络行为仍是明确实测项，不凭模拟宣布通过。
